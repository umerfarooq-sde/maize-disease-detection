# Phase 24.5 — actual API contracts and Flutter consumers

Runtime router-stack inventory: **44 Node endpoints**; factory-generated AI schema: **10 internal/service endpoints**. Express default non-strict trailing-slash matching accepts `/scans` and `/scans/`; table preserves the mounted declaration. The profile `all()` authorization guard is middleware, not a 45th business endpoint. HEAD/OPTIONS supplied by framework behavior are not separate feature APIs.

## Common contracts

Node JSON success is `{success:true, data, requestId}`; error is `{success:false, error:{code, message, details?}, requestId}`. Binary image success is intentionally unwrapped. AI JSON uses `{success, data, meta:{requestId}}` and structured errors; dedicated clients validate/map this envelope. Central Node errors include validation400, auth401, authorization403, not-found404, conflict409, size413, media415, limit429, safe500 and bounded dependency502/503/504. Every route inherits appropriate global request IDs, JSON/security/CORS/rate-limit middleware; protected groups also perform live session lookup. POST/PATCH/DELETE are JSON unless specified. Exact schema sources below are authoritative, not guessed compatibility.

All Node source paths below start `backend/src/modules/`. `module` means the actual route → controller → service → repository family, not controller SQL. External-client orchestration may intentionally have no separate DB repository. All listed Flutter consumers call the shared configured Node API. Tests marked live depend on the explicitly reported configuration/run; the unmodified baseline startup failure remains a failure.

## AI service endpoints

All `/api/v1` routes require configured internal Bearer service authentication before expensive work. Flutter is never their consumer. `/health` is public coarse liveness; internal model/retrieval/generation/management routes require service authentication. AI validation is normally422, unlike Node public400; dedicated clients map image/dependency errors rather than leaking internals. ## Compatibility conclusion

Declared paths/methods, camelCase fields, literal labels/statuses, nullable predictions, ISO UTC timestamps, decimal strings, source versions and cursor DTOs align across the traced clients. Private image DTOs are exact relative Node paths; bearer/capability headers and session revisions are preserved. Original inference bytes, model/preprocessing versions and saved ownership remain bound. AUD-16 is a reproduced timeout-contract mismatch: profile removal waits for cleanup beyond the Flutter DELETE deadline despite a committed change. Passing normal-provider tests did not catch that delayed-provider case.

This inventory is audit documentation, **not generated Node OpenAPI**. Finding AUD-07 remains open. Generated AI development OpenAPI also does not automatically fully describe manually parsed JSON/authentication in every operation. Original example endpoint names such as `/rag/fertilizer-advice` were suggestions; their absence alone is not a defect when optional explanation is not enabled.

Profile image/scan DTO byte counts describe the original admitted upload; metadata-free display/storage derivatives can differ in byte size. They remain associated with the same authorized resource, and display derivatives are never substituted for original ML input.
