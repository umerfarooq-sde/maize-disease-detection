# Private operator configuration

These empty examples are contracts, not working credentials. Copy only the files
needed by an authorized environment into an external private secret directory.
Never put filled files in this directory or Git. Linux: directory `0700`, mounted
files `0444` inside that private directory so assigned non-root container users
can read them. Configure equivalent Windows ACLs. Docker access itself is trusted.

All six PostgreSQL identities must match the reviewed names and have separate
credentials. URLs require `sslmode=verify-full`; use a provider/public CA or an
explicit `/certificates/root.crt` mounted CA. Export operator SQL for review before
creating/changing managed roles. Runtime deployment never rotates credentials.

Node and AI/curator share the internal AI token; this differs from the operations
token. Node, AI/curator and the private monitoring file `operations-token` share
that separate operations token. Access and refresh signing keys are also distinct.
Generate keys with a secure secret manager or `secrets.token_urlsafe(32)` without
printing them into logs. Required files also include:

- `backup-key`: exactly 32 random binary bytes, separately escrowed.
- `grafana-password`: operator-managed strong private password.
- `redis.conf`: disable the default Redis user; enable only the named `quota`
  identity with a strong password matching Node's private Redis URL. Reference
  settings are generated by `manage.py prepare-local`; external Redis requires TLS.

`privacy.json` uses the operator adapter's camel-case provider keys shown above;
it is never loaded by Node/AI. Its identity cannot be used to approve requests
through the public API. `operator.json` is used only for explicit provisioning,
isolated restore drills and generated SQL; it is never mounted into a hosted app.
`curator.json` is used only by reviewed ingestion. The policy template keeps all
automatic erasure and expiration disabled.
